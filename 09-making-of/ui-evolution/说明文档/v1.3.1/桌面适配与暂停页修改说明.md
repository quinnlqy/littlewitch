## 2 桌面容器：16:9 比例与独立 UI 缩放

### 2.1 统一游戏容器

桌面采用居中的 16:9 gameFrame，随实际可见窗口等比放大。采用 1280×720 作为界面设计基准；世界仍是 480×270。设计基准用于计算比例，实际运行尺寸随窗口变化。

frameWidth = min(可用宽度, 可用高度 × 16/9)

frameHeight = frameWidth × 9/16

frameLeft = (可用宽度 − frameWidth)/2；frameTop = (可用高度 − frameHeight)/2

背景、HUD、技能、提示、暂停/结算面板与资源动效统一归属 gameFrame。手机背景与触控继续按其安全区域适配，不套用桌面的外部留边策略。

### 2.2 桌面 UI 大小

desktopUiScale = frameWidth / 1280。世界缩放和 UI 缩放各有自己的映射，最终落在同一容器内。文字、图标、按钮、间距、描边及布局留白统一使用设计 token；避免某几个元素仍固定小像素。

| 元素 | 1280×720 基准 | 1920×1080 对应尺寸 |
| --- | --- | --- |
| 炉火/绽放按钮直径 | 72 | 108 |
| 两技能间距 | 16 | 24 |
| 技能图标 | 24 | 36 |
| 生命图标 | 18 | 27 |
| 常用 HUD 标签 | 14–16 | 21–24 |
| 技能名称/数值 | 14 | 21 |
| 分数 | 28 | 42 |
| 绽放累计条 | 44×4 | 66×6 |
| 暂停目标尺寸 | 44×44 | 66×66 |

以上单位为 CSS 像素。紧凑桌面档以 960×540 为最低验收目标：技能按钮至少 64，关键文字至少 14；低优先级提示可收起，内容重新排布。桌面固定 64px 按钮的旧要求由本版比例方案替代。手机主键仍以 56、平板以 72 为触控基准，手机标签与百分比至少 12，帮助正文至少 14。

### 2.3 战斗视野与空间

以 1280×720 为例，上方预留 72、底部预留 104、左右至少 16；数值乘 desktopUiScale。将完整的 480×270 战斗核心等比置入剩余矩形并水平居中。此时核心约 967.11×544，左边约 156.44、上边 72。技能组位于底部预留区，Boss 信息位于顶部预留区。

背景在整个 gameFrame 中连续绘制，前景玩法对象按战斗核心映射；保护区边界不绘制可见窗口线。玩家速度、世界坐标、碰撞和敌人预兆规则保持一致。触点/鼠标采用当前战斗核心矩形反算世界坐标。缩放不能改变击中范围。

## 3 背景：容器内连续铺满，外部用安静留边

桌面背景覆盖整个 16:9 gameFrame。相机、视差、月亮、远山、湖面、村庄与桥体共用一套坐标和场景时钟；核心以外的装饰区域在同一场景中自然延展，月亮只出现一轮。图层按各自比例铺设，必要裁切只发生在非交互背景。

桌面 gameFrame 外多余区域使用低对比深紫渐变。外部区域不放 HUD、提示或敌人；不复制游戏截图，不把月亮/村庄放大模糊后再当补边。gameFrame 内没有第二套模糊场景，避免锐利中心与模糊外圈拼接。手机按完整容器和安全区域自然扩展背景，主要战斗视野完整保留。

继续使用当前项目资产与水彩风格。图像生成参考用于材质、色彩和层级；背景的正确实现需对照当前资产，不能将整张概念图铺在程序上替代动态场景。Canvas backing resolution 依据 CSS 显示大小及像素密度合理设置，逻辑坐标保持 480×270，禁止通过非等比拉伸解决铺满。

## 4 暂停页：简洁菜单与操作说明

![A 月光悬浮桌面暂停页](A月光悬浮-桌面暂停页.png)

两张图均为内置 imagegen 生成的视觉参考，分别用于桌面和手机横屏排布。美术保持 A 的透明深紫、奶油白细线和月光装饰；产品使用当前场景、角色与实际设置状态。

### 4.1 暂停主菜单的信息

暂停主菜单服务于继续游玩、重新开始、返回标题和调整设置。实时炉火次数、绽放累计条与持续倒计时常驻战斗 HUD；技能机制与键位通过“操作说明”按需查看。

| 层级 | 内容 | 行为 |
| --- | --- | --- |
| 标题 | 暂停；关卡名小字可保留 | 提示当前暂停，背景与游戏时钟冻结 |
| 主操作 | 继续夜巡 | 点击或桌面 P/Esc 恢复 |
| 次操作 | 重新开始、返回标题 | 在面板内确认后执行 |
| 帮助入口 | 操作说明 | 打开独立说明视图，游戏继续保持暂停 |
| 小设置区 | 声音：开/关；可用时全屏/退出全屏 | 直接更新对应设置 |
| 触控设置 | 换手 | 交换摇杆与整组战斗技能键，仍停留在暂停 |

主菜单的视觉主体是导航和设置，不展示技能状态卡、库存数字、能量百分比、资源进度条或技能选择。暂停时战斗 HUD 与操作键收起。关闭暂停后，战斗 HUD 恢复同一份资源状态。

### 4.2 桌面排布

保留暂停瞬间的场景，覆盖均匀而克制的深紫遮罩；主要角色与背景仍可辨认。中央面板明显收紧，宽度以1280设计基准下约360为起点，高度由上述菜单内容决定，尽量控制在约350–390；桌面UI按第2章比例放大。图像尺寸是视觉近似，真实尺寸按CSS与可读性校准。

从上到下为：小星月装饰、“暂停”、可选的关卡名、宽主按钮“继续夜巡”、横排次按钮“重新开始/返回标题”、较轻的“操作说明”入口、底部声音与全屏。P/Esc继续提示作为低优先级小字放在面板下方；完整键位留在操作说明内。

主要按钮以设计基准48高为起点，次按钮至少44的点击目标。面板上下留出空间，低高度时优先减装饰和间距，再允许面板内滚动。桌面不显示换手。暂停时隐藏战斗层的浮动声音与暂停按钮，菜单中声音只有一处入口。

### 4.3 手机与平板排布

![手机横屏暂停菜单](A月光悬浮-手机暂停页.png)

手机横屏采用紧凑中央面板。主按钮占一行，重开与返回标题并排；底部为操作说明、声音、换手三个轻量入口。关卡名可保留小字。触控端隐藏键帽及P/Esc提示，帮助内容使用“左侧摇杆/右侧按钮”和“自动射击”的说明。

所有交互目标至少44×44 CSS像素，正文至少14，安全边距至少8并叠加safe-area。手机参考图中的全屏项未显示；正式实现按平台能力提供，空间不足时设置区换行。568×320及低可见高度允许菜单内部滚动，继续按钮保持首屏可见。平板沿用同一菜单结构，依可用空间增大控件。

### 4.4 操作说明的内容与返回

操作说明作为暂停状态下的独立子视图呈现，内容可滚动，具有明确“返回”入口。默认只在玩家点开时显示，回到暂停主菜单后保留当前游戏进度。

| 说明项 | 桌面 | 手机/平板 |
| --- | --- | --- |
| 移动 | WASD或方向键 | 摇杆移动；可按换手设置交换侧别 |
| 普通射击 | 按住空格/J | 战斗中自动射击 |
| 炉火 | Z或点击炉火按钮 | 点炉火按钮 |
| 炉火来源 | 击败灯怪补充，上限3次，每次释放消耗1次 | 同左 |
| 绽放 | E/K或点击绽放按钮 | 点绽放按钮 |
| 绽放充能 | 回收微光累计，满槽主动开启，持续5秒 | 同左 |
| 射击成长 | 回收微光使射击逐级成长 | 同左 |

帮助讲机制与操作，不复制实时资源面板。炉火火种飞入与绽放进度仍按第5、6章在战斗HUD实现。

桌面Esc在说明子页执行“返回暂停菜单”；在确认页执行“取消”；仅在暂停主菜单执行“继续”。关闭说明后仍暂停，不穿透触发射击、炉火或绽放。返回暂停主菜单时焦点回到“操作说明”，恢复游戏后焦点回到游戏容器。

### 4.5 确认、焦点与有效功能

重新开始与返回标题在当前面板内展示确认文字和“取消/确认”操作，默认焦点落在取消；取消后回暂停。确认重开才清本局资源，确认回标题才结束当前局。声音和全屏调整不会自动恢复游戏。打开暂停时焦点落在继续按钮，Tab只遍历当前视图，点击遮罩保持暂停。

暂停、恢复、切换说明与确认视图都清理已按下输入。新一轮移动、射击、技能操作由新的输入触发。菜单打开期间火种飞行和绽放持续时钟冻结，恢复时继续原状态。

游戏只提供炉火与绽放两类技能入口，帮助与键盘处理对应这一规则。清理旧Q/1–4及selectMagicCard/setMagic路径，确保2/3/4之后按Z仍能正常释放炉火；既有四魔法卡的移除状态保留。

菜单的信息取舍依据本项目的实际功能：两项技能在暂停中没有配装、升级或资源分配操作，主菜单只承担导航和设置；机制解释通过操作说明读取。A月光悬浮是本项目自有的视觉方向。

## 5 火种飞向炉火：一条清楚的奖励路径

### 5.1 当前原因与目标

当前 spawnFireWisp 已尝试飞向 #btnMagic .ico，但仅 10 CSSpx，0.45 秒飞完。第一次到第三次灯怪击破同时执行旧 spawnLampWisp：暖光以世界坐标向右上飘 1.25 秒，半径达 13–20 世界像素，视觉上远大于新 UI 火种；旧 wick 还向玩家吸附。这些是不同归属的表现。

本版让“灯怪灯肚 → 炉火按钮内火焰图标”成为唯一主要的炉火奖励轨迹。移除旧的向右上飞散暖光；背景路灯可在到账后安静亮起，作为次级故事反馈。若保留灯芯 100 分，计分配置与总分保持一致，表现归属分数；不再用火种外形飞向玩家，避免混淆。

### 5.2 清楚可见的时序

有效击破时建立唯一 rewardId，并根据 fireAmmo + pendingFire 预约空位。0.10 秒破灯亮焰后，用固定 0.60 秒沿清楚弧线飞入炉火图标中心。本版将原 0.45 秒飞行调整为 0.60 秒，以增加方向可读性。

火种在1280桌面基准下亮核约 12–14 CSSpx，短尾约 24–36，随桌面 UI 比例调整；手机亮核至少 12、短尾保持紧凑。少量柔光帮助识别，不绘制贯穿画面的实线，不抢敌弹与预兆。

所有终点读取当前炉火图标真实矩形。当前怪物灯肚中心转换为资源层坐标作为起点；窗口、外部留边、核心内缩、DPR、设备模式和左右交换都通过同一坐标映射处理。图标不存在或不可见时按界面状态挂起/结清，不能悄悄飞向硬编码后备点。

抵达才提交库存 +1：飞行中 1/3，抵达后 2/3。炉火图标短亮 0.18 秒、次数轻跳、在按钮旁显示“炉火 +1”约 0.6 秒；提示放在资源区，改掉当前在玩家头上飘字的路径。

### 5.3 预约与生命周期

库存初始0、上限3，仅有效击破灯怪补充；微光只影响成长与绽放。预约也占3格容量。同帧两灯和重复回调按唯一ID只结一次；满额在击破时决定溢出100分，飞行中施法不重分配已判定奖励。满额不播放假入槽动画。

暂停冻结；失败取消在途；重开/返回标题清 FIRE_WISPS、资源层 DOM、pendingFire 和旧 rewardId；再次开始库存仍0。进入归途/成功页前按既有规则结清已登记有效奖励，随后清光迹。新局不得接收上一局的到账。此项属于 P0。

## 6 绽放与其他遗漏一起修

绽放的能量与持续进度已经在源码实现，保留：非持续态每颗微光+5、满100主动开5秒、持续期不攒下一轮。按钮常驻暗轨道与实心蓝紫进度条、真实百分比；100显示就绪；开启后显示剩余秒数，结束回0。修手机9px文字与桌面3px条过小的问题，外圈辅助，不替代实心条。

L3 达到成长上限后显示“满级”且成长条填满；从阈值表计算中间等级进度。时间统一两位分钟与秒，如00:10、01:05；手机战斗 HUD 收起秒数，时间可在结算查看，暂停主菜单只保留可选关卡名。最终 Boss 刻度来自真实阈值：35%、70%，中 Boss 无三阶段时不显示这两道刻度。

设备布局与输入能力分离。宽屏触屏笔记本可使用桌面布局和键鼠；触摸支持不等于手机屏幕。为开发测试保留显式布局覆盖入口，并在验收中记录实际模式；手机、平板、桌面都读取实时状态。
